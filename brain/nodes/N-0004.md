## Contexto

Acto 5 ("hardening", firme a futuro) + cierre narrativo. La mitigación estructural: hash de keys en DB, scopes por endpoint, audit log. El re-ataque rebotando es la prueba visual de que el hardening funciona. El postmortem EN (sección del README o archivo docs) es la pieza que un reclutador lee entera sin correr nada.

## Valor

Cierra el ciclo del incidente y eleva la demo de "cortar el fuego" a "que no vuelva a pasar". Métrica de éxito #5 de la spec: con hardening activo, re-ataque = 0 escrituras maliciosas, todo auditado.

## Implementación (S05 parte A, 2026-11-14 — AC1·AC2·AC3·AC5; AC4 postmortem queda para S06)

- `src/lab.js -> hardenKeys / sha256Hex / rotateKey / killSwitch / listAudit` — migración one-shot en DB: toda key con `key_plain` pasa a `key_hash = sha256(key)` (node:crypto) y plain → NULL; scope `write:entries` SOLO para la activa vigente no-leaked (la key del leak queda sin alcance aunque siga active — D-0004: re-ataque sin rotación previa rebota 403). Schema + tabla `audit`. `state.currentMasked`: la máscara vigente se guarda en runtime porque con hash no se re-deriva. Rotar con hardening activo inserta la key ya hasheada con scope (nunca reintroduce plain); kill switch matchea también por hash.
- `src/apikey.js -> apiKeyAuth / reject` — modo hardened: compara `sha256(presented)` contra `key_hash`; POST exige scope `write:entries` → 403 `insufficient_scope`. Todo rechazo (401/403) pasa por `reject()`, que escribe fila en `audit` SOLO si hardening activo (contrato §2.4) con ts, key enmascarada ("—" sin key), method, endpoint, status, reason. Modo vulnerable S03/S04 intacto (24 tests previos verdes).
- `src/labroutes.js` — POST `/api/lab/hardening` (validación estricta `enabled===true`; evento `action`; acto → 5) + GET `/api/lab/audit?since=<id>` incremental. `state.keys.storage` refleja "plaintext"|"sha256" y `current_masked` sale del runtime en modo hardened.
- `public/index.html + panel.js` — sección "Hardening" (botón + indicador de storage) y sección "Audit log" (polling 1s incremental con hora, código, endpoint, key enmascarada y motivo). Badge acto 5 "Sistema endurecido" + basura congelada = sistema recuperado (AC5).
- `test/hardening.test.js` — 7 tests: dump DB (plain NULL + hash exacto + scope), 403 por scope sin rotación, re-ataque 100% rebotado con 0 basura + audit por intento, audit solo con hardening, `?since=` incremental, rotación post-hardening sin reintroducir plain, validación 400.
