## Contexto

Orden del Negocio: correr BreachLab con Docker para el visitante sin Node 24. Tensión
con D-0003 (aislamiento por bind loopback): Docker no reacha el loopback de un
contenedor — el proceso debe bindear 0.0.0.0 adentro, sin exponer nada en el host.

## Valor

Un comando (`docker compose up --build`) para toda la experiencia, sin prerequisito de
runtime. El aislamiento queda demostrable (netstat), no prometido.

## Implementación (2026-11-15, ADR D-0008)

- `server.js`: `HOST = process.env.HOST || '127.0.0.1'` — el env existe SOLO para el
  contenedor. De paso, fix `PORT=0` (`Number.isInteger` en vez de `||` que comía el 0).
- `Dockerfile`: node:24-alpine · package*.json → `npm ci --omit=dev` (capa cacheada) ·
  COPY selectivo (server.js, src, public, repo-sim, docs) · `ENV HOST=0.0.0.0` ·
  `data/` pre-creada con ownership del usuario no-root `node` · `CMD ["node","server.js"]`.
- `docker-compose.yml`: UNA regla crítica — `ports: "127.0.0.1:3000:3000"`: el
  aislamiento D-0003 vive en ese port binding a nivel host (comentado en el yml).
  Sin volúmenes: data efímera por diseño (re-seed al arrancar).
- `.dockerignore`: node_modules, data, .git, brain, factory, test, docs/screenshots.
- CI: job `docker-build` (build only). README EN/ES: sección Docker tras el quickstart
  con la nota de seguridad (dónde vive el aislamiento en modo Docker).
- Bot atacante intacto: su URL loopback constante alcanza al server dentro del mismo
  proceso/namespace de red del contenedor — el relato HTTP real se preserva.

## Hallazgos de verificación

- `PORT=0` colisionaba en 3000 (falsy-swallow) — fixeado en server.js, cubierto por los
  2 tests nuevos (spawn de proceso real, DB propia por BREACHLAB_DB).
- Primera corrida de compose: EADDRINUSE por un `node server.js` huérfano de sesión
  previa en el host (PID 26584) — descartado como evidencia, re-verificado limpio.
